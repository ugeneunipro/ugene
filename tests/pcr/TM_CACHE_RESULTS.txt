Shared TmCalculator cache: validation and benchmarks
===================================================

Change
------
Move caching from the PCR-specific wrapper into TmCalculator. Both Rough
and Primer3 implement calculateMeltingTemperature(); existing callers use
the same public getMeltingTemperature() method. Settings are immutable.
The public method stays virtual to preserve the existing U2Core callback
dependency: U2Core must not link directly against U2Algorithm.

The per-instance LRU cache has a 64 KiB cost budget for sequence/key/value
bytes, excluding Qt bookkeeping. Oversized inputs bypass it without evicting
cached primers. Keys own their storage, including for fromRawData() inputs.
Cache access is mutex-protected. Calculations run outside the lock; concurrent
misses may compute the same value twice. Cache entries never cross instances.

Validation
----------
- pcr, pcr_tests and primer3 build successfully on macOS arm64.
- Standalone runner: all 11 scenarios pass.
- Native XML runner: all 11 PCR tests and all 50 existing DNA statistics tests
  pass. The latter cover the existing Rough/Primer3 temperature results.
- New cache coverage: reuse, settings isolation, invalid results, LRU eviction,
  frequently reused primers, oversized input, external-buffer ownership, and
  concurrent access. Degenerate R/Y primers resolve against each product.
- Full Col-CEN Chr3 result TSVs, including all metadata and temperatures, are
  byte-identical to the previous fix for mismatches 0..3 with perfect tail=15,
  and mismatches=3 with perfect tail=0 (10,316 products).

Performance
-----------
Before: commit 693a9a8036 with its PCR-specific two-primer cache.
After: shared bounded cache, no PCR wrapper.
Apple M4 Pro, macOS arm64, -O3 -DNDEBUG, UGENE Rough calculator.
Three processes per case/variant, each one warm-up plus seven measured runs.
Values are medians of per-process medians. The calculator is reused between
iterations, so its new shared cache remains warm. RSS is process high-water,
including libraries, fixtures, allocator effects and measured iterations.
The old executable uses its saved original U2Algorithm library.

The dense Rough case is 0.163 ms slower (about 5.4%); generic cache lookup
and insertion add overhead when the calculation itself is cheap. Sparse
10,000-product runtime remains approximately 21 ms. No broad speedup over
PCR-specific caching is claimed; this change makes reuse available to all
calculator callers while bounding retained sequence data.
